# ADR-0010: 链下对冲系统

## 状态

已采纳

## 背景

链下 Hedging System 是维持 M delta-neutral 的核心。它负责计算报价、管理投资组合、执行对冲交易、协调 OES 托管分配。

## 决策

### 组件职责

#### 1. Pricing API

```
POST /quote
{
    "action": "mint|redeem",
    "asset": "ETH|BTC|USDT",
    "amount": "1000000000000000000"
}

Response:
{
    "quote_id": "0x...",
    "collateral_amount": "1000000000000000000",
    "m_amount": "3500500000000000000000",
    "expiry": 1728000000,
    "signature_payload": { ... }
}
```

#### 2. Portfolio Manager

```typescript
interface PortfolioManager {
    // 输入
    ingestCEXOrderBook(exchange: Exchange, data: OrderBook): void;
    ingestCEXPositions(exchange: Exchange, positions: Position[]): void;
    ingestOESBalances(oes: OESProvider, balances: Balance[]): void;
    ingestOnchainEvents(events: MintEvent[] | RedeemEvent[]): void;

    // 计算
    netDeltaUsd(): BigNumber;          // ≈ 0 (target)
    grossExposure(): AssetExposure[];  // 按资产/交易所/托管商
    weightedFundingRate(): BigNumber;  // 加权平均资金费率
    
    // 对冲决策
    executeMintHedge(mint: MintOrder): HedgeInstruction;
    executeRedeemHedge(redeem: RedeemOrder): HedgeInstruction;
    rebalance(): HedgeInstruction[];

    // 风控
    validatePrice(order: Order): boolean;
    isSystemHealthy(): boolean;
}
```

#### 3. OES 协调

```typescript
interface OESCoordinator {
    // 铸造后：将资产从 minting 转到托管商
    custodyFromMinting(asset: string, amount: BigNumber, custodian: OESProvider): void;

    // 委托名义价值给交易所作为保证金
    delegate(exchange: Exchange, amount: BigNumber): void;

    // 取消委托
    undelegate(exchange: Exchange, amount: BigNumber): void;

    // PnL 结算
    settle(exchange: Exchange): SettlementResult;

    // 赎回前：从托管商回收资产
    recallToMinting(asset: string, amount: BigNumber): void;
}
```

### Mint/Redeem 对冲流程

#### Mint

```
1. 用户 RFQ $100k 铸造
2. 系统报价：$100k ETH → 3500.50 USDe/ETH
3. 用户签名，提交订单
4. 链上 mint: 用户 28.57 ETH → custodian; 用户收到 100k M
5. 事件监听器触发 PortfolioManager
6. PortfolioManager 计算：需要做空 28.57 ETH 等值
7. 通过 OES 向交易所委托名义价值
8. 在 CEX 开空 28.57 ETH 永续合约
9. Poltfolio delta ≈ 0 ✓
```

#### Redeem

```
1. 用户 RFQ 赎回 $50k M
2. 系统报价：$50k → 返回 14.28 ETH
3. 用户签名，提交订单
4. 监控系统验证用户有足够经审计的 M
5. 系统提前准备：从 OES 回收 + 平部分空仓
6. 获取到足够 ETH 后，调用 redeem()
7. 链上 redeem: 销毁用户 50k M; 返回 14.28 ETH
8. 链下：剩余对冲 → 检查 delta 仍 ≈ 0
```

## 后果

### 正面
- Delta-neutral 策略使协议收益独立于市场方向
- 多源收益分散化降低依赖单一市场
- OES 隔离防范 CEX 破产风险

### 负面
- 链下系统是中心化组件，需信任运营团队
- 对冲执行延迟可能产生短暂 delta 暴露
- 系统架构复杂，运维成本高

### 不采用的设计
- ❌ 链上对冲 — Gas 成本高、速度慢、策略暴露
- ❌ 单一 CEX — 交易对手集中风险
