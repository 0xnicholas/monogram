# ADR-0011: 储备金

## 状态

已采纳

## 背景

Reserve Fund 是一个由协议基金会持有的链下资产池，在高收益期从协议收入中分配资金建立。负收益周期由储备金吸收，确保 sM 用户永不承担损失。

## 决策

### 储备金角色

```
协议收益 → 收益分配（由协议基金会决定）
              │
      ┌───────┴───────┐
      ▼               ▼
  Reserve Fund    sM Staking Rewards
  (链下资金池)      (链上分发)
      │
      ├── 正收益期：分配比例由治理决定（当前 0% → Reserve Fund）
      ├── 负收益期：Reserve Fund 补贴协议
      └── 极端情况：Reserve Fund 用于维持抵押率 ≥ 100%
```

### 资金流

```solidity
// RewardsDistributor 触发收益分配
contract RewardsDistributor is AccessControl {
    bytes32 public constant OPERATOR_ROLE = keccak256("OPERATOR_ROLE");

    // 链上分发到 StakedM
    function distributeToStakers(uint256 amount) external onlyRole(OPERATOR_ROLE) {
        IERC20(asset()).safeApprove(address(stakedM), amount);
        stakedM.transferInRewards(amount);
        emit RewardsDistributed(amount);
    }
}

// 负收益时：链下 Reserve Fund 以 M 形式注入协议
// 方法：Foundation 从 Reserve Fund 购买 M，转入 StakedM
// 确保 sM:M 汇率不下降
```

### 储备金来源

| 阶段 | 分配比例 | 说明 |
|------|---------|------|
| 启动期 | 100% 进入 Reserve Fund | 协议初期高收益，快速建立缓冲 |
| 稳定期 | 治理决定（建议 10-20%）| 平衡储备与用户奖励 |
| 满储备 | 0% → Reserve Fund | 储备金达目标水位后全部用于奖励 |

### 储备金目标

| 指标 | 数值 | 说明 |
|------|------|------|
| 最低储备 | M 供应量 1% | 安全垫 |
| 目标储备 | M 供应量 3% | 健康状态 |
| 满储备 | M 供应量 5% | 超额储备 |
| 储备率检查 | 每日自动 | 低于阈值触发通知 |

### 透明度

协议提供：
- 实时仪表盘：`app.ethena.fi/dashboards/transparency`
- 每周 Proof of Reserves
- 月度托管商证明

## 后果

### 正面
- sM 用户不承担负收益
- 储备金提供市场极端情况下的缓冲
- 储备金规模公开透明

### 负面
- 储备金的资金不产生额外收益（躺平在池中等待使用）
- 储备金规模潜在不足，可能无法覆盖极端黑天鹅事件
- 链下储备金依赖 Foundation 的信用

### 不采用的设计
- ❌ 链上储备金合约 — 增加合约面和攻击面
- ❌ 自动清算 — 与合成美元设计理念冲突
