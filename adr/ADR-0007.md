# ADR-0007: 质押与收益分发 sM

## 状态

已采纳（2026-08-27 按决议 #7 重写，对齐 StakedUSDeV2）

## 背景

sM 是基于 ERC-4626 的不变收益合约。用户存入 M 获得 sM，`REWARDER` 角色定期注入 M 奖励，
sM:M 汇率单调递增。奖励在 8 小时内线性 vesting，防止闪电贷操纵汇率。

初版实现（RedemptionRequest 单槽排队模型）存在三个缺陷（详见 #2 差距报告）：

1. **冷却期可被绕过**：`withdraw()/redeem()` 原生路径不受冷却期约束，`requestRedeem` 形同虚设
2. **稀释**：烧毁 shares 后资产仍留在金库内参与 `totalAssets`，损害剩余质押人
3. **偿付风险**：排队资产与金库资产混同，极端情况下 claim 无法足额兑付

## 决策

全面复刻 StakedUSDeV2（GPL-3.0，源码见 Etherscan；审计版镜像 code-423n4/2023-10-ethena），
以冷却期互斥 + UnstakingSilo 一并修复上述三缺陷。

### 合约结构

```
StakedM          ERC-4626 Vault + ERC20Permit + SingleAdminAccessControl
UnstakingSilo    冷却资产隔离库，仅 StakedM 可转出（onlyStakingVault）
```

### 解质押：冷却期互斥 + Silo

- `cooldownDuration > 0`（默认 90 天，构造即开启）：
  - `withdraw()/redeem()` 被 `ensureCooldownOff` 拦截 → **绕过路径封死**
  - 解质押必须走 `cooldownShares(shares, owner)` / `cooldownAssets(assets, owner)`：
    烧 shares、资产转入 Silo、记录 `cooldowns[owner] = {cooldownEnd, underlyingAmount}`
  - `unstake(receiver)`：`block.timestamp >= cooldownEnd` 后从 Silo 领取全部资产
- `cooldownDuration == 0`：恢复标准 ERC-4626 即时提款；Silo 中已到期资产仍可 `unstake` 领取
- Silo 中的资产即时退出 `totalAssets()` → **稀释与偿付缺陷修复**

### 受限地址语义（对齐 V2）

| 角色 | deposit/mint | withdraw/redeem/cool-down | sM 转账 |
|------|--------------|---------------------------|---------|
| 无限制 | ✅ | ✅（受冷却期约束） | ✅ |
| SOFT_RESTRICTED | ❌（caller 与 receiver 均拦） | ✅ 可退出 | ✅ |
| FULL_RESTRICTED | 质押给他人可；接收 sM 被 `_update` 拦 | ❌ | ❌（`_update` 拦，burn 豁免） |

- `BLACKLIST_MANAGER_ROLE` 经 `addToBlacklist/removeFromBlacklist` 管理（不可作用于 admin）
- `redistributeLockedAmount(from, to)`：admin 专属；`to == address(0)` 走 burn-to-vest 分支

### 奖励累积

- `transferInRewards(amount)`：仅 REWARDER，8 小时线性 vesting，`totalAssets` 排除未 vest 部分
- `MIN_SHARES = 1 ether`：每次存取后 `_checkMinShares` 防捐赠攻击

### 权限基座

`SingleAdminAccessControl`（单 admin + 两步移交），与 MonogramMinting 一致；
`renounceRole` 全禁，`rescueTokens` 可营救误转入金库的代币（M 本身除外）。

## 偏离点（有理由才偏离）

1. **vesting 合并语义**：`transferInRewards` 在未 vest 完时可再次注入，剩余未 vest 金额与新奖励
   合并重算（Ethena 版 revert `StillVesting`）。分发器无需等待 8 小时窗口；负收益经简化分发器
   注入的路径（ADR-0011）也更平滑。维持初版行为，#7 决议认定等价。
2. **RewardsDistributor 维持简化版**：operator 自备 M + `transferFrom` + 1 天最小分发间隔。
   Ethena 版分发器内闭环 mint 依赖「分发器持有抵押品 + delegated signer」托管路径，在 #8/#9
   定型前复刻会押错接口——押后 Phase 3 再议（#13）。
3. **OZ v5 虚拟份额舍入**：`_convertToAssets` 含 `(totalAssets+1)/(supply+1)` 防通胀项，
   整数场景可有 1 wei 偏差（偏向金库）。Ethena 基于 OZ v4 无此项，属框架版本差异，非设计偏离。

## 后果

### 正面
- 冷却期不可绕过；冷却资产隔离出 `totalAssets`，汇率对剩余质押人公平
- 受限语义与 Ethena 生产一致（软受限可入不可出；全受限资金可被接管）
- ERC-4626 + Permit，与 Aave、Pendle、Morpho 等协议可组合

### 负面
- 冷却期开启时偏离 ERC-4626 标准（`withdraw/redeem` revert），集成方需感知
- 合规限制（SOFT/FULL_RESTRICTED）引入审查担忧
- Vesting 与冷却计算增加 Gas 开销
