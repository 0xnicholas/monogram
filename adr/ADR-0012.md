# ADR-0012: 治理与信任模型

## 状态

已采纳

## 背景

治理模型围绕 MONO 代币、Risk Committee、多签和时间锁构建。协议的信任假设被明确文档化并接受社区审查。

## 决策

### 信任模型全景

```
                       ENA 持有者
                           │
                    ┌──────▼──────┐
                    │  治理投票   │
                    └──────┬──────┘
                           │
              ┌────────────┼────────────┐
              ▼            ▼            ▼
       Risk Committee   Foundation    ENA 质押者
              │            │            │
              │    ┌───────▼───────┐    │
              │    │  多签 7/10   │    │
              │    │  时间锁 7天  │    │
              │    └───────┬───────┘    │
              │            │            │
              ▼            ▼            ▼
       资产配置策略   合约管理员     协议收益分配
```

### 信任假设

| # | 信任假设 | 缓解 |
|---|---------|------|
| 1 | 对冲系统将正确执行 delta-neutral 对冲 | 可通过公开仪表盘验证持仓 |
| 2 | OES 托管商将履行职责 | 多托管商冗余 + 月度证明 |
| 3 | GATEKEEPER 将正确响应异常 | 内外部分布，无利益冲突 |
| 4 | ADMIN 多签将只按协议利益操作 | 7/10 地理分布 + 7 天时间锁 |
| 5 | 预言机数据准确 | 双预言机（Pyth + Chainlink） |

### 治理参数

| 参数 | 可调范围 | 控制方 | 时间锁 |
|------|---------|--------|--------|
| maxMintPerBlock | 0 ~ 无上限 | ADMIN 多签 | 7 天 |
| maxRedeemPerBlock | 0 ~ 无上限 | ADMIN 多签 | 7 天 |
| stablesDeltaLimit | 0 ~ 10000 bps | ADMIN 多签 | 7 天 |
| maxPriceDeviationBps | 0 ~ 10000 bps | ADMIN 多签 | 7 天 |
| cooldownDuration | 0 ~ 90 天 | ADMIN 多签 | 7 天 |
| 支持资产 | ADD/REMOVE | ADMIN 多签 | 7 天 |
| Custodian 地址 | ADD/REMOVE | ADMIN 多签 | 7 天 |
| 储备金分配比例 | 0% ~ 100% | ENA 治理 | 7 天 |
| Risk Committee 成员 | ADD/REMOVE | ENA 治理 | 7 天 |

### Risk Committee

| 职责 | 成员 | 任期 |
|------|------|------|
| 设置资产配置限制 | 3-5 名成员 | 6 个月 |
| 审核新资产上线 | 安全专家 | 可连任 |
| 审核新托管商 | 行业机构 | — |
| 定时报告 | — | 每季度 |
| 紧急响应 | — | 按需 |

### 合约信任属性

| 合约 | 可升级 | 管理员 | 信任最小化程度 |
|------|--------|--------|-------------|
| M.sol | ❌ 不可升级 | 所有者（多签） | **最高** — 代码不可改，仅 minter 指针可变 |
| MonogramMinting | ❌ 不可升级 | ADMIN 多签 | **高** — 参数可调，但核心逻辑不变 |
| StakedM | ❌ 不可升级 | ADMIN 多签 | **高** — 参数可调，奖励方向只能正 |

采用无 Proxy 模式：V1 → V2 通过部署全新合约完成迁移，而非代理升级。这种设计降低了对管理员的信任依赖。

### 透明度

```
公开仪表盘:
  ├── 实时抵押率: 链上 M 供应量 vs 链下资产证明
  ├── 当前总供应: app.ethena.fi/dashboards/transparency
  ├── 储备金余额
  ├── Custodian 分配比例
  └── CEX 持仓分布

定期证明:
  ├── 每周 Proof of Reserves（第三方审计）
  ├── 月度 Cusodian 证明
  └── 季度风险报告
```

## 后果

### 正面
- 清晰的信任模型文档化，用户可自行评估风险
- 多签 + 时间锁 + 地理分布减少 ADMIN 风险
- 不可升级合约减少对管理员的信任依赖

### 负面
- 不可升级合约意味着修复 bug 需要迁移（如 V1 → V2）
- 链下组件（对冲、OES）引入了无法消除的信任假设
- 治理参与度可能不足（ENA 投票率问题）

### 不采用的设计
- ❌ 链上治理全自动 — 应急情况需要人类判断
- ❌ 全 DAO 治理 — 延迟太长不适合风控参数
- ❌ 无时间锁的 ADMIN — 单点故障风险过高
