# ADR-0006: 资产托管与结算

## 状态

已采纳

## 背景

采用 Off-Exchange Settlement (OES) 托管架构。抵押资产存储在与协议合作的托管商处，通过 OES 将名义价值委托给 CEX 作为保证金，实现破产隔离。

## 决策

### 托管架构

```
Mint 流程:
用户资产 → MonogramMinting → 托管商（OES）
                                      │
                                      ├── Copper Clearloop
                                      ├── Ceffu Mirror
                                      ├── Krakin Custody
                                      └── Anchorage Digital
                                              │
                                     委托（非转账）名义价值
                                              │
                                              ▼
                                      CEX（Binance/Bybit/OKX）
                                      用名义价值开空对冲

Redeem 流程:
CEX 平仓 → OES 结算 → MonogramMinting → 用户
```

### 链上资产传输

Mint 时，`MonogramMinting` 将资产转到预批准的 custodian 地址：

```solidity
function _transferCollateral(address asset, uint256 amount, address benefactor) private {
    if (!_supportedAssets.contains(asset)) revert UnsupportedAsset();
    IERC20(asset).safeTransferFrom(benefactor, _getMintCustodian(), amount);
}
```

Custodian 地址通过 ADMIN 管理：

```solidity
mapping(address => bool) public custodianAddresses;
address private _mintCustodian;  // 当前铸造的目标托管地址

function addCustodianAddress(address custodian) external onlyRole(DEFAULT_ADMIN_ROLE) {
    if (!custodianAddresses[custodian]) {
        custodianAddresses[custodian] = true;
        emit CustodianAddressAdded(custodian);
    }
}

function removeCustodianAddress(address custodian) external onlyRole(DEFAULT_ADMIN_ROLE) {
    if (custodianAddresses[custodian]) {
        custodianAddresses[custodian] = false;
        emit CustodianAddressRemoved(custodian);
    }
}

function setMintCustodian(address custodian) external onlyRole(DEFAULT_ADMIN_ROLE) {
    if (!custodianAddresses[custodian]) revert InvalidCustodianAddress();
    _mintCustodian = custodian;
    emit MintCustodianUpdated(custodian);
}
```

### 转移至托管（Minter 操作）

```solidity
function transferToCustody(
    address wallet, address asset, uint256 amount
) external nonReentrant onlyRole(MINTER_ROLE) {
    if (!custodianAddresses[wallet]) revert InvalidCustodianAddress();
    if (!_supportedAssets.contains(asset) && asset != NATIVE_TOKEN) revert UnsupportedAsset();

    IERC20(asset).safeTransfer(wallet, amount);
    emit CustodyTransfer(wallet, asset, amount);
}
```

### 赎回转账

```solidity
function _transferToBeneficiary(address beneficiary, address asset, uint256 amount) private {
    if (!_supportedAssets.contains(asset)) revert UnsupportedAsset();
    IERC20(asset).safeTransfer(beneficiary, amount);
}
```

### OES 运作原理

```
1. 托管商持有资产（物理隔离）
2. 托管商向 CEX 委托名义价值（非转账）
3. CEX 将委托价值记为保证金
4. CEX 向托管商质押抵押品
5. PnL 按日/每小时结算至托管账户
6. 协议控制委托/取消委托
```

**破产隔离效果**：
- 交易所倒闭：本金在托管商处，不在交易所资产负债表上
- 托管商问题：多托管商冗余，可切换
- 最大风险：单结算周期内的未实现 PnL（按天：约 1 天收益）

### Custodian 分布

| 托管商 | 用途 | 份额 |
|--------|------|------|
| OES Provider A | 永续合约保证金委托 | ~30% |
| OES Provider B | 永续合约保证金委托 | ~30% |
| OES Provider C | 永续合约保证金委托 | ~30% |
| 链上（DeFi） | Aave/Morpho 借贷 | ~10% |

## 后果

### 正面
- 破产隔离：CEX 倒闭不影响本金
- 多托管商冗余，限制单一故障点
- 协议控制资产进出

### 负面
- OES 集成需要与托管商建立合同关系，启动成本高
- 每日/每小时结算存在结算窗口风险
- 依赖托管商的技术基础设施

### 不采用的设计
- ❌ Route 比例路由 — 铸造时直接转到单一 custodian 地址
- ❌ 原生 ETH 处理 — 只处理 ERC20 资产
- ❌ COLLATERAL_MANAGER_ROLE — ADMIN + MINTER 覆盖其职责
