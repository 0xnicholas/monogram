# ADR-0003: 铸造/赎回引擎 MonogramMinting

## 状态

已采纳

## 背景

MonogramMinting 是协议的核心网关合约。它接收链下签名的 EIP-712 订单，验证签名和价格合规性后，原子地执行资产转移和 M 铸造/销毁。

## 决策

### 接口

```solidity
enum OrderType { MINT, REDEEM }

struct Order {
    OrderType order_type;   // MINT 或 REDEEM
    uint256   expiry;       // 过期时间
    uint256   nonce;        // 防重放编号
    address   benefactor;   // 资产提供方
    address   beneficiary;  // 资产接收方
    address   collateral_asset; // 抵押资产地址
    uint256   collateral_amount; // 抵押数量
    uint256   m_amount;         // 铸造/赎回的 M 数量
}

struct Signature {
    uint8   signature_type;  // 0 = EIP712, 1 = EIP1271
    bytes   signature_bytes;
}
```

### 核心流程

#### Mint

```
1. 仅 MINTER_ROLE 可以调用
2. 验证订单签名（ECDSA.recover 或 EIP-1271.isValidSignature）
3. 验证 nonce 未使用（bitmap）
4. 检查每区块 mint 限额
5. 验证价格与预言机偏差在允许范围内（≤5%）
6. 将抵押资产从 benefactor 转至 custodian 地址
7. 铸造 M 至 beneficiary 地址
```

```solidity
function mint(
    Order calldata order,
    Signature calldata signature
) external nonReentrant onlyRole(MINTER_ROLE) belowMaxMintPerBlock(order.m_amount) {
    if (order.order_type != OrderType.MINT) revert InvalidOrder();
    _verifyOrder(order, signature);
    _deduplicateOrder(order.benefactor, order.nonce);
    _validatePrice(order.collateral_asset, order.collateral_amount, order.m_amount);

    mintedPerBlock[block.number] += order.m_amount;
    _transferCollateral(order.collateral_asset, order.collateral_amount, order.benefactor);
    m.mint(order.beneficiary, order.m_amount);

    emit Mint(...);
}
```

#### Redeem

```
1. 仅 REDEEMER_ROLE 可以调用
2. 验证订单签名
3. 验证 nonce 未使用
4. 检查每区块 redeem 限额
5. 验证价格偏差
6. 销毁用户的 M（burnFrom）
7. 将抵押资产转回 beneficiary
```

```solidity
function redeem(
    Order calldata order,
    Signature calldata signature
) external nonReentrant onlyRole(REDEEMER_ROLE) belowMaxRedeemPerBlock(order.m_amount) {
    if (order.order_type != OrderType.REDEEM) revert InvalidOrder();
    _verifyOrder(order, signature);
    _deduplicateOrder(order.benefactor, order.nonce);
    _validatePrice(order.collateral_asset, order.collateral_amount, order.m_amount);

    redeemedPerBlock[block.number] += order.m_amount;
    m.burnFrom(order.benefactor, order.m_amount);
    _transferToBeneficiary(order.beneficiary, order.collateral_asset, order.collateral_amount);

    emit Redeem(...);
}
```

### Mandate Delta Limit（V2 特性）

```solidity
uint256 public stablesDeltaLimit;  // bps, default 500

function _checkStablesDelta(
    address asset, uint256 collateralAmount, uint256 mAmount
) internal view {
    if (_isStablecoin(asset)) {
        (uint256 price,) = priceFeed.getPrice(asset);
        uint256 normalized = collateralAmount * price / 1e18;
        uint256 deviation = _absDiff(normalized, mAmount) * 10000 / mAmount;
        if (deviation > stablesDeltaLimit) revert StablesDeltaLimitExceeded();
    }
}
```

```solidity
function addSupportedAsset(address asset) external onlyRole(DEFAULT_ADMIN_ROLE) {
    if (!_supportedAssets.add(asset)) revert InvalidAssetAddress();
    emit AssetAdded(asset);
```

## 后果

### 正面
- 原子操作没有中间状态
- 完整的签名 + 价格 + 限额多层验证
- 严格角色分离，各角色权限最小化

### 负面
- Gas 成本较高（签名验证 + 预言机调用 + 限额跟踪）
- 依赖链下系统提供有效的签名订单

### 不采用的设计
- ❌ Route 比例路由 — 直接转账到单一 custodian 更简洁
- ❌ 原生 ETH 处理 — 只处理 ERC20 资产
- ❌ COLLATERAL_MANAGER_ROLE — ADMIN + MINTER 覆盖其职责
- ❌ DelegatedSigner — 增加不必要的授权路径
