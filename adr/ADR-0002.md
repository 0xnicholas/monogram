# ADR-0002: 稳定币代币 M 设计

## 状态

已采纳

## 背景

M 是合成本位币代币合约，设计为最小化、不可升级的 ERC20，只暴露一个关键函数——`mint`——调用方限制为单一的 `minter` 地址。

## 决策

### 合约结构

```solidity
contract M is Ownable2Step, ERC20Burnable, ERC20Permit {
    address public minter;

    event MinterUpdated(address indexed newMinter, address indexed oldMinter);

    error ZeroAddressException();
    error CantRenounceOwnership();
    error OnlyMinter();

    constructor(address admin) Ownable(admin) ERC20("Monogram", "M") ERC20Permit("Monogram") {
        if (admin == address(0)) revert ZeroAddressException();
        _transferOwnership(admin);
    }

    function setMinter(address newMinter) external onlyOwner {
        if (newMinter == address(0)) revert ZeroAddressException();
        emit MinterUpdated(newMinter, minter);
        minter = newMinter;
    }

    function mint(address to, uint256 amount) external {
        if (msg.sender != minter) revert OnlyMinter();
        _mint(to, amount);
    }

    function renounceOwnership() public view override onlyOwner {
        revert CantRenounceOwnership();
    }
}
```

### 关键设计

| 特性 | 实现 | 理由 |
|------|------|------|
| 标准 | ERC20 + ERC20Permit | 最大化 DeFi 可组合性 |
| 销毁 | `ERC20Burnable`（`burn` + `burnFrom`）| 赎回时链上销毁 |
| 所有者 | `Ownable2Step` | 两步转移防误操作 |
| 铸造权限 | 单 `minter` 地址 | 始终指向 `MonogramMinting` |
| 禁止放弃所有权 | `renounceOwnership()` revert | 防止合约变孤儿 |
| 可升级性 | 不可升级（无 Proxy） | 代币合约需最大安全性 |

- M 的 `burnFrom` 由 `ERC20Burnable` 提供，`MonogramMinting` 需要在调用 `burnFrom` 前获得用户授权（通过 Permit 或 `approve`）
- `setMinter` 仅由 `owner`（多签）控制，用于在 `MonogramMinting` 升级时更新指针
- M 设计为不可升级（无 Proxy），代币合约需最大安全性

## 后果

### 正面
- 最小化代币复杂度，审计风险最低
- 不可升级，用户无需信任合约不会变更

### 负面
- `setMinter` 是中心化控制点，若多签丢失则无法更新
- M 不可暂停（暂停逻辑在 MonogramMinting 层面）

### 不采用的设计
- ❌ Pausable — 暂停逻辑在 MonogramMinting 层面，不放在代币层
- ❌ AccessControl — 只有单 minter 模式
- ❌ Snapshot/Tax — 保持简单透明
- ❌ Proxy — 代币不应可升级
