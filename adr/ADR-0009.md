# ADR-0009: 风控与安全机制

## 状态

已采纳

## 背景

协议采用多层风控体系：合约级（ReentrancyGuard、签名验证）、交易级（per-block 限额、价格偏差）、运营级（GATEKEEPER、多签、时间锁）和经济级（Reserve Fund、多源收益）。

## 决策

### 风控全景

```
Layer 0: 合约层
  ├── ReentrancyGuard
  ├── EIP-712 签名验证
  ├── Nonce bitmap 防重放
  └── CEI 模式（Checks-Effects-Interactions）

Layer 1: 交易层
  ├── Per-block mint/redeem 限额
  ├── Mandate Delta Limit（稳定币）
  ├── 双预言机价格偏差 (±5%)
  ├── 订单过期校验
  └── 入口白名单（benefactor/beneficiary）

Layer 2: 运营层
  ├── GATEKEEPER 即时关停
  ├── 多签（7/10）地理分布式
  ├── 7 天时间锁（ADMIN 操作）
  └── 角色分离（4 个独立角色）

Layer 3: 经济层
  ├── Delta-neutral 对冲
  ├── 多源收益（费率/基差/借贷/RWA）
  ├── Reserve Fund 缓冲
  └── 透明度仪表盘
```

### Layer 0: 合约安全

```solidity
// ReentrancyGuard — OpenZeppelin 标准实现
nonReentrant modifier on mint() and redeem()

// Checks-Effects-Interactions
// 状态变更在外部调用前完成
function mint(Order calldata order, Signature calldata signature)
    external nonReentrant onlyRole(MINTER_ROLE) belowMaxMintPerBlock(order.m_amount)
{
    // Checks
    _verifyOrder(order, signature);
    _deduplicateOrder(order.benefactor, order.nonce);
    _validatePrice(order.collateral_asset, order.collateral_amount, order.m_amount);

    // Effects
    mintedPerBlock[block.number] += order.m_amount;

    // Interactions
    _transferCollateral(...);
    m.mint(order.beneficiary, order.m_amount);
}
```

### Layer 1: 交易风控

#### Per-block 限额（V2 增强）

```solidity
// 基础限额（V1）
uint256 public maxMintPerBlock;
uint256 public maxRedeemPerBlock;
mapping(uint256 => uint256) public mintedPerBlock;
mapping(uint256 => uint256) public redeemedPerBlock;

// 资产分组限额（V2）
mapping(address => AssetType) public assetTypes;
mapping(AssetType => mapping(uint256 => uint256)) public mintedPerBlockByType;
mapping(AssetType => uint256) public maxMintPerBlockByType;
uint256 public globalMaxMintPerBlock;

modifier belowMaxMintPerBlock(uint256 amount) {
    if (mintedPerBlock[block.number] + amount > maxMintPerBlock)
        revert MaxMintPerBlockExceeded();
    _;
}

modifier belowMaxMintPerBlockByType(AssetType assetType, uint256 amount) {
    if (mintedPerBlockByType[assetType][block.number] + amount > maxMintPerBlockByType[assetType])
        revert MaxMintPerBlockByTypeExceeded();
    if (mintedPerBlock[block.number] + amount > globalMaxMintPerBlock)
        revert GlobalMaxMintPerBlockExceeded();
    _;
}
```

#### Mandate Delta Limit（V2）

```solidity
// 防止稳定币脱钩套利
// 当稳定币与 USDe 的偏差超过阈值时拒绝订单
uint256 public stablesDeltaLimit;  // bps

function _mandateDeltaCheck(address asset, uint256 collateralAmount, uint256 mAmount) internal view {
    if (_isStablecoin(asset)) {
        (uint256 price,) = priceFeed.getPrice(asset);
        uint256 normalized = collateralAmount * price / 1e18;
        uint256 deviation = _absDiff(normalized, mAmount) * 10000 / Math.max(normalized, mAmount);
        if (deviation > stablesDeltaLimit) revert MandateDeltaLimitExceeded();
    }
}
```

### Layer 2: 运营风控

#### GATEKEEPER 响应

```
Minter 私钥泄露场景:
  1. 攻击者用泄露的 MINTER 铸造 M
  2. Per-block 限额限制单块最大损失（如 $100k）
  3. GATEKEEPER 监控发现异常交易
  4. GATEKEEPER 立即调用 disableMintRedeem()
  5. 最大损失：1 个 block 的限额（~$100k）
```

#### 多签与时间锁

```solidity

// 内部签名人 4 个，外部签名人 3 个

// 所有 ADMIN 操作通过时间锁
// 时间锁延迟：7 天
// GATEKEEPER 操作无时间锁
```

### 合规与受限处置（两层模型，#11 决议）

受限地址的处置分两层，互相独立、无跨合约联动（复刻 Ethena V2 语义）：

```
入口层 MonogramMinting（mint/redeem 白名单）
  ├── 主管限：受制裁 benefactor → 多签 removeWhitelistedBenefactor
  ├── 白名单主网部署即启用，单向棘轮不可逆
  └── minting 合约不查 StakedM 的 restricted roles

出口层 StakedM（质押侧受限名单，ADR-0007）
  ├── SOFT_RESTRICTED  → 不能新质押，存量可赎回
  └── FULL_RESTRICTED  → 不能动，可被协议接管全额赎回
```

M 代币转账不设限（无 transfer hook）；散户从 DEX/CEX 二级市场获得 M。

### Layer 3: 经济风控

| 风险 | 缓解 |
|------|------|
| 负资金费率 | Reserve Fund 吸收；多源收益分散 |
| 抵押品价格下跌 | Delta-neutral 对冲（价格变化被做空抵消） |
| 交易所倒闭 | OES 隔离，资产不在交易所 |
| 托管商问题 | 多托管商冗余 |
| LST 脱钩 | 仅 6% 使用 LST，限制敞口 |
| 稳定币脱钩 | Mandate Delta Limit + 资产分组限额 |

### 最大损失场景

| 场景 | 最大损失 | 缓解措施 |
|------|---------|----------|
| MINTER 私钥泄露 | ~1 区块的 mint 限额 | Per-block 限额 + GATEKEEPER 关停 |
| ADMIN 多签泄露 | 全系统 | 7/10 地理分布 + 7 天时间锁 |
| 预言机操纵 | ~5% 偏差 | 双预言机 ±5% 限制 |
| 重入攻击 | 0 | ReentrancyGuard + CEI |
| CEX 爆雷 | ~1 天 PnL | OES 隔离 + 每日结算 |

## 后果

### 正面
- 多层防御降低单点失效风险
- 可量化的最大损失（per-block 限额）
- GATEKEEPER 即时响应不依赖慢速治理

### 负面
- 多层验证增加 Gas 成本
- 7 天时间锁限制紧急合约升级
- GATEKEEPER 依赖外部实体响应及时性
